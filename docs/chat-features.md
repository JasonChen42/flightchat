# 聊天功能与断线恢复

## 使用方式

- 长按消息即可引用；引用栏可取消。点消息内的引用可定位到原消息（本机没有原消息时会提示）。
- 输入栏“图片”打开选择和预览，支持说明文字、默认压缩、原图（最多 20 MB）。图片可点开并双指缩放。消息有传输百分比；待发送消息和未下载图片提供重试入口。
- 顶部“搜索”查询本机全部历史文字和图片说明，支持中文子串，高亮匹配，最多展示 200 个结果。点击结果加载对应上下文。“回到最新消息”恢复最新位置。
- 列表按需增加 100 条历史记录。数据库保留全部记录，图片保存在应用私有 `files/images/`，不依赖相册 URI 的长期权限。

## 同步协议

双方使用新版：加入消息携带 `flightchat/2` 能力标记，房主回复 HELLO，提供持久化的 serverId 和本次运行的图片通道端口、令牌。

每个房主对应独立的同步游标。游标使用房主数据库自增序号，不能用客户端时间或最近收到的消息代替。房主获取历史上界后按 100 条分批发 SYNC_PAGE，最后发 SYNC_END；每一页写入完成后客户端才保存游标。实时消息不会推进同步游标，避免实时消息先到造成历史缺口。

消息 messageId 有唯一索引，网络接收忽略发送端的本地数据库行号。重复补发不会产生重复记录。补发的历史消息不会重复触发通知。

客户端发送前先保存 PENDING。房主落盘后回复 ACK，客户端改为 SENT。每次重连、每 10 秒及手动重试都会检查待发消息和缺失图片。房主去重后仍回复 ACK，应对确认丢失。每 10 秒心跳；读超时 45 秒触发重连。断线期间仍可将消息加入本机待发队列。

图片按 SHA-256 标识，独立 TCP 通道传送二进制，不放进聊天 JSON。客户端上传成功后发送图片消息；房主中转，其他客户端自动下载；哈希、大小和完整长度校验后才替换正式文件。未完成文件不会被当作可用图片。接收后的图片离线可查看。

## 升级与边界

Room v2 → v3 迁移补充引用、图片、发送状态字段，为没有 ID 的旧记录生成 ID，并合并已有相同网络 ID 的重复记录。保留其余记录和用户配置。

两端都需升级才能完整使用新能力。补消息来源是当前房主仍保留的记录；手机清除应用数据、房主丢失记录、换到未持有这些记录的房主，不能凭空恢复历史。保留原项目的单聊天室模型，没有新增房间隔离或云备份。历史中在线状态事件只作为记录，当前在线用户以实时加入/离开为准。

## 验证

- 单元测试覆盖旧消息兼容、新控制帧与引用/图片字段传输。
- 真机数据库测试覆盖 v2 迁移、去重、235 条分批历史、实时先到及重放、中文搜索、待发确认。
- 真机图片测试覆盖 TCP 下载、落盘读取及损坏数据拒绝。
- Compose 真机测试覆盖缩小视口时最新消息可见、长按引用并发送。
